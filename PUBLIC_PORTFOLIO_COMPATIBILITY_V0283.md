# v0.2.83 — Public portfolio v2 response-bound identity and accurate owner display

## Why this milestone exists

The user postponed second-device and second-member testing in favor of getting **one owner fully functional**. All multi-user schemas, invitations, per-user Public connections, encrypted owner backup and the previously enabled invitation flags remain intact; the owner has not issued a real invitation. v0.2.82 was merged/tested and its owner-only manual Public portfolio switch was explicitly enabled on the existing paid Render service. A first successful **real** balance-and-holdings response has not yet been independently confirmed.

The official [Public Get account portfolio v2 documentation](https://public.com/api/docs/resources/account-details/get-account-portfolio-v2) identifies `GET /userapigateway/trading/{accountId}/portfolio/v2` as a snapshot for a specified authenticated client-owned account. Its contract specifies `accountId`, `positions`, `totalAccountValue` and additional cash, equity and buying-power details. Positions include an instrument/symbol, quantity and current value. A quantity may mean equity shares, fractional crypto units, options contracts or bond face-value amounts; the UI must not label every quantity **shares**. Neither a position's quantity nor its current value is necessarily a profit/loss figure.

## Implementation safeguards

- Continue using the **existing** provider account discovery and identity-bound encrypted Public key; no new endpoint, worker or provider credential is introduced.
- After the Public GET response, verify its documented `accountId` string exactly matches the already verified provider account requested. Missing, malformed or different account IDs **refuse the complete snapshot** with a sanitized error, never displaying or logging an unrelated account. The internal EdgePilot account UUID is still used for the client-facing response.
- Preserve quantities as validated finite decimal strings up to 18 fractional decimal places, with sensible length/magnitude bounds and support for negative short units. Never blindly truncate untrusted strings, show `NaN`, default an absent quantity to zero, or round fractional crypto values to two decimal places. Exact whole-account money values remain sanitized USD cents.
- A manual **View read-only portfolio** click is still required for every read. The account page validates the entire sanitized snapshot before rendering, clears stale values at the beginning of a new request, renders amounts as USD without floating-point conversion, labels quantities generically as *units*, and displays a clear empty-positions message when Public reports no positions (cash can still contribute to total account value).
- A local retrieval timestamp is explicitly **device time**, not a market quote time or proof of data freshness. No automatic refresh, trade, transfer, monitoring, watchlist change, predictive buy/sell advice or portfolio chart history is created.
- All existing default-off pilot gates, per-identity and per-account checks, before/after-request sole-owner checks, encrypted key separation, rate limits and no-execution safety flags remain in place. A newly registered member would still fail-close the temporary solo portfolio path until the separately designed multi-user policy is accepted.

## Test/acceptance boundaries

Updated fake Public portfolio fixtures include the documented `accountId`. Regression tests reject mismatched, missing, or malformed provider account identifiers and nonfinite, enormous, missing or malformed fractional quantities; accept valid short/fractional units. Static browser UI tests verify manual-only requests, account matching, stale-data clearing, no implicit `shares` wording, nonpersistent keys, and no polling/trade/transfer code. Real Public API values are **not** used by tests.

For owner acceptance, on the existing paid production deployment: sign in to the independent EdgePilot owner account at `/account`, locate the verified Public link under `Linked accounts`, press **View read-only portfolio**, and confirm total value, each position/quantity and no trade/transfer actions. Report only whether values display or sanitized failure text; keep API keys, account identifiers, holdings screenshots showing private data, recovery keys, and tokens outside public GitHub. Only after a successful owner-provided report should the app describe real Public balance/holding integration as accepted. No new paid service or APK build is needed for this backend/browser-page change.
