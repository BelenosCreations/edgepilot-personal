# v0.2.99 — Offline historical realized paper loss-stop preflight

This introduces a **dormant, read-only risk research primitive**, not an active paper-trading loss stop or user-configured production policy. `engine/tenant_paper_loss_stop.py` accepts a verified Linux /dev/shm SQLite *synthetic* fixture, an externally trusted identity/account pair and an explicit positive whole-cent maximum realized-loss threshold. It opens SQLite read-only, begins a consistent read transaction, audits the full tenant paper ledger, verifies active user/linked account scope and independently replays one account's assumed BUY/SELL events in append order using conservative cost-basis releases.

The result includes exact-cent current cumulative *realized* assumed-fill P&L and the worst historical cumulative realized P&L. It marks a threshold as breached once that historical floor reaches the negative user-supplied threshold, **even if subsequent assumed trades recover the cumulative P&L**. That historical-stickiness is an analysis invariant; it is **not a durable policy lock** that can yet prevent any write, nor is it a prediction or mark-to-market stop. No broker buying power, open-position unrealized loss, quote rights, price feed or execution slippage can be inferred.

Synthetic negative tests cover two users and three separately scoped accounts, 7-cent and 14-cent realized losses, an eventual synthetic profitable sale, independent account histories, exact threshold boundaries, malformed limits, tampered cash deltas, missing/mismatched account authority and non-tmpfs files. No private brokerage data, keys or balances are used. The existing dormant fill writer is intentionally not connected; never mistake `wouldBlockNewAssumedFills` for actual enforcement.

**Production gates remain closed.** Any active paper loss stop requires a separately approved immutable/account-scoped durable latch, atomic enforcement within the same database transaction as each assumed fill, trusted session-derived identity, user-configured thresholds and validated data licensing. Recovery must preserve/verify that latch without resurrecting revoked account credentials. No HTTP endpoint, production schema update, real quote cache, paper execution, live/autonomous order, bank transfer, paid service, Render plan/disk/secret change or new integration is introduced.
